# Own updater over GitHub Releases, textier's one network call

textier kept to no network calls at all. An in-app updater needs one, so this is the exception, and the only one: a check of the repo's latest GitHub release (`api.github.com/repos/loco1842/textier/releases/latest`) at launch and once a day while `checkForUpdates` is on (the default) or when the user asks, and, when the user chooses to install, the download of that release's zip and `SHA256SUMS.txt`. Nothing about the user or their text is sent; GitHub sees an IP address and a `User-Agent: textier`.

The updater is our own (`Updater`, `TextierCore`'s `AppVersion` and `Release`), not Sparkle. Sparkle would add a framework to embed and sign, an appcast to publish and an EdDSA key to keep as a CI secret, for one gain: an update signed apart from the GitHub account. textier's releases are ad-hoc signed and downloaded from GitHub by hand today, so the account and HTTPS are already the whole of the trust; the updater checks the zip against the release's checksum, that it's textier (its bundle identifier) at the version offered, and changes nothing unless all of it holds. Moving to Sparkle later means publishing an appcast and replacing `Updater`; the config key and the menu item would stay.
